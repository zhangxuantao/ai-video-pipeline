# AI 视频管线设计

> 日期：2026-11-25
> 状态：待评审
> 范围：只覆盖视频管线。图文管线、自动发布、多账号矩阵均不在本设计内。

## 1. 背景与目标

用家里一台 Windows 机器（Ultra 9 285K、RTX 5080 16G、2T 固态）上已有的 ComfyUI，搭一条"尽量全 AI"的短视频生产管线，产出"AI 经典奇谈"（山海经、神话志怪）题材的竖屏短片，主发快手，抖音和视频号用同一份内容同步分发，靠平台流量分成获利。

成功标准：

- 一条 2 分钟的成片可以从选题到交付无人值守跑完。
- 人只做成片审核：看一遍加对个别镜头点"重做"，总耗时不超过 15 分钟。
- 单卡能做到隔日更。

## 2. 非目标

以下各项明确不做，避免范围蔓延：

- 不做自动发布。所有平台都由人手动发布并勾选 AI 声明。
- 不做多账号矩阵。各平台规范都禁止批量注册相似账号。
- 不做图文管线。视频的关键帧如需当图文发布，手工处理。
- 第一版不训角色 LoRA。角色一致性先用"定妆图加参考图"实现，不够稳再训。
- 不做微信贴图号、公众号、服务号。微信 2026-03-27 起禁止用 AI、脚本替代真人创作发布。
- 不做小红书、B站、今日头条。这三者要么没有可依赖的分成口径，要么对全 AI 内容治理过严。

## 3. 平台与合规约束

以下结论查证于 2026-11-25，平台规则会变，实施前需复核。

| 约束 | 来源 | 对本设计的硬性要求 |
|---|---|---|
| 快手扶持 AIGC 内容：AIGC 燎原计划（冷启动，不限 AI 工具）、AI 灵境计划（流量分成）；扶持赛道含"AI 经典奇谈"；评价维度含作者辨识度、质量稳定性、创作持续性、作品完整度 | 快手 2026-09 光合大会 AIGC 分论坛，平台口径 | 账号定位选该赛道；管线目标对齐这四个维度 |
| 快手"优质 AIGC 万播分成超 15 元" | 同上，平台宣传口径 | 仅作量级参考，不作为收益预期 |
| AI 生成的音视频必须显著标识，不得删除或隐匿平台与工具添加的标识 | 《人工智能生成合成内容标识办法》（2025-09-01 施行）；《微信视频号运营规范》6.4 | 成片内固定加显式标识；发布时勾选 AI 声明；不去除任何隐式标识 |
| 视频号禁止批量发布情景、文案、元素近似的同质化内容 | 《微信视频号运营规范》5.12 | 单号、每条内容独立选题，不批量铺量 |
| 视频号禁止未经许可用第三方工具接入微信系统 | 《微信视频号运营规范》4.3 | 不做发布自动化 |
| 视频号把轮播文字、大字覆盖、简单拼凑列为低质内容 | 《微信视频号运营规范》5.14 | 成片必须是真实运动画面，不做图文轮播式视频 |
| 灵异恐怖类内容受限制（视频号明确列为违规，其余平台按同类规则谨慎对待） | 《微信视频号运营规范》5.13 | 题材做"奇观、神话"，不做灵异恐怖 |
| 配乐有版权风险 | 通用 | 只用可商用的无版权音乐；不使用影视剧、游戏的现成形象与美术风格 |

最大的不确定性：全 AI 视频能否被认定为优质原创并进入快手分成计划，目前没有公开口径。这一点只能靠里程碑 3 的实测回答，拿到数据前不继续给管线加功能。

## 4. 总体架构

### 4.1 机器分工

```
远程桌面（ToDesk / 向日葵 / RustDesk，选公司网络下能用的一个）
        │  接管家里电脑的桌面
        ▼
家里电脑（常开，管线服务开机自启）
┌──────────────────────────────────────────┐
│ 管线服务（Python）                         │
│   本机网页  http://127.0.0.1:<端口>         │
│   任务队列 + 状态库（SQLite）               │
│   脚本：DeepSeek API                       │
│   关键帧 / 镜头：ComfyUI（HTTP + WebSocket）│
│   配音：本地 TTS                            │
│   合成：ffmpeg                              │
├──────────────────────────────────────────┤
│ ComfyUI（仅监听本机 8188，不对外暴露）       │
│ 模型目录 / 素材目录 / 成片目录 / 网盘同步目录 │
└──────────────────────────────────────────┘
        │ 成片自动放进网盘同步目录
        ▼
手机或电脑看原画质 → 远程桌面里点"重做" → 手动发布到快手（主）/ 抖音 / 视频号
```

安全要求：

- ComfyUI 的 8188 端口和管线服务都只监听本机地址，不通过 frp 等方式暴露到公网。
- 远程桌面软件设置强密码、二次验证和无人值守密码，它是家里电脑唯一的对外入口。
- 管线服务不依赖远程会话运行，断开远程后显卡继续工作；断电重启后自动恢复。

成片不在远程桌面里观看：远程桌面传的是压缩画面。管线把成片放进网盘同步目录，人在手机或电脑上看原画质。

### 4.2 流水线

一条内容称为一个 Episode，按以下阶段依次处理：

| 阶段 | 做什么 | 执行者 | 人是否介入 |
|---|---|---|---|
| 1. 脚本 | 按主题生成分镜脚本，每镜含画面描述、运镜描述、旁白 | DeepSeek API | 否 |
| 2. 关键帧 | 每个分镜出 4 张候选图，自动评分取 1 张 | ComfyUI 文生图 | 否 |
| 3. 镜头 | 选中的图做图生视频，每镜出 2 条候选，自动评分取 1 条 | ComfyUI 图生视频 | 否 |
| 4. 配音 | 旁白按镜切段合成语音 | 本地 TTS | 否 |
| 5. 合成 | 镜头、旁白、字幕、配乐、固定片头片尾拼成成片；片头加固定的"本片画面由 AI 生成"文字提示作为显式标识 | ffmpeg | 否 |
| 6. 交付 | 成片、标题、简介、话题标签放入待发目录和网盘同步目录 | 管线服务 | 看成片，对个别镜头点"重做"，然后手动发布 |

### 4.3 关键设计决策

**每镜固定 5 秒，旁白每镜不超过 20 字。** 配音时长与镜头时长因此天然对齐，不需要视频模型生成任意时长，也不需要变速拼接。中文配音约 4 字每秒，20 字留有余量。一条 2 分钟的片子约 24 镜。脚本阶段强制校验这条约束，超字的旁白直接打回重写。

**按阶段批量，不按镜头批量。** 文生图模型和图生视频模型不能同时常驻 16G 显存。管线先把全部镜头的关键帧出完，再全部做图生视频，每条片子只切换两次模型。

**自动评分直通，人工事后返工。** 原设计里有两个选片卡点，异地访问时人会卡住显卡。改为：每个候选用本地评分模型打分，自动取最高分进入下一阶段；人只看成片，对不满意的镜头点"重做"，管线只重跑那几镜再重新合成。

**发布永远手动。** 管线的产出止于"可以点发布"的状态。

**评分与候选数靠数据调。** 自动评分不如人眼准，评分模型选型、是否引入多指标加权、候选数量，都根据前几条片子的返工率来调整，不预设复杂方案。

## 5. 模块划分

每个模块只有一个职责，通过明确的输入输出衔接。

| 模块 | 职责 | 输入 | 输出 |
|---|---|---|---|
| `script` | 调 DeepSeek 生成分镜脚本 | 主题、题材设定、画风设定 | EpisodeSpec（JSON） |
| `keyframe` | 调 ComfyUI 出关键帧候选 | EpisodeSpec、文生图工作流模板、角色定妆参考图 | 每镜 4 张候选图 |
| `shot` | 调 ComfyUI 做图生视频 | 每镜选中的关键帧、图生视频工作流模板 | 每镜 2 条候选片段 |
| `score` | 给候选打分并排序 | 候选文件 | 每镜选中的候选 |
| `voice` | 合成旁白 | EpisodeSpec 的旁白文本 | 每镜音频、每镜实际时长 |
| `compose` | 拼成片 | 选中的片段、音频、字幕、模板素材 | 成片 mp4 |
| `deliver` | 准备发布材料 | 成片、EpisodeSpec | 待发目录、网盘同步目录 |
| `queue` | 任务队列与状态 | 用户提交、各模块的状态流转 | Episode 与镜头的状态 |
| `web` | 本机操作界面 | 人的操作 | 提交任务、查看进度、预览成片、单镜重做 |

EpisodeSpec 是模块间的核心契约：

```json
{
  "episode_id": "20261125-001",
  "title": "……",
  "topic": "……",
  "shots": [
    {
      "shot_no": 1,
      "narration": "……",
      "image_prompt": "……",
      "motion_prompt": "……",
      "duration_sec": 5
    }
  ]
}
```

建议的仓库结构（实施计划阶段再细化）：

```
src/          管线代码，按模块分包
workflows/    ComfyUI 的 API 格式工作流模板
templates/    片头片尾、字幕样式等固定素材
tests/        单元测试与端到端冒烟
docs/         设计与计划文档
```

模型权重、素材、成片一律放在仓库之外，由配置文件指定目录。

## 6. 队列与容错

**队列：** SQLite 记录每个 Episode 和每个镜头在各阶段的状态。串行执行，同一时间只有一个任务占用显卡。

**容错规则：**

- 生成失败：换随机种子重试 2 次。
- 显存不足：降分辨率或减采样步数重试 1 次。
- 仍然失败：该镜头标记为失败，其余镜头继续，交付时汇总列出失败的镜头。
- 中断恢复：服务重启或断电恢复后从上次状态继续。已完成的素材按"工作流模板加参数加种子"做缓存键，不重算。
- ComfyUI 崩溃：由管线服务负责拉起并重连。
- 单镜重做：只重跑指定镜头的关键帧、镜头、合成，不影响其他镜头。

## 7. 测试策略

- 工作流模板：参数注入后生成的请求能通过 ComfyUI 校验，并用最低画质实际跑通。
- 合成模块：用纯色视频和静音音频做假素材，断言成片的时长、分辨率、镜头数、字幕轨。
- 脚本模块：校验每镜旁白不超过 20 字、镜数正确、JSON 结构合法。
- 队列模块：模拟失败与中断，断言重试次数、状态流转和缓存命中。
- 端到端冒烟：2 个镜头、最低画质、每镜 1 个候选，一键跑完整条流水线。
- 产能校准：标准画质跑一条完整片子，记录每阶段耗时，用于校准产能估算。

## 8. 里程碑

按"先打通最不确定的环节"排序。

| 里程碑 | 做什么 | 验收标准 |
|---|---|---|
| 0. 打通图生视频 | 在家里电脑上手工装 Wan 2.2 的 5B 图生视频模型和官方工作流模板 | 用一张固定图跑出 5 秒视频；连续跑 10 个镜头不崩；记下平均耗时和显存占用 |
| 1. 最小端到端 | 搭管线骨架：脚本、关键帧、镜头、本地配音、合成，加本机网页 | 2 个镜头、最低画质、每镜 1 个候选，一条 10 秒的片子无人值守跑完 |
| 2. 一条能发的片子 | 标准画质、24 镜、每镜多候选、自动评分、字幕配乐片头片尾、AI 标识、单镜重做、断点续跑 | 一条 2 分钟成片；人工审核加返工不超过 15 分钟 |
| 3. 实测再定投入 | 发 5 到 10 条到快手，申请燎原计划和灵境计划，记录播放、完播、是否进计划、有无分成 | 用真实数据决定加大投入、调整题材，还是回头加真人成分 |

里程碑 1 内需要通过实测确定的选型：

- 本地中文 TTS：能在 16G 显存上与视频模型共存，音色适合志怪解说。
- 候选评分模型：本地可跑，对画面质量敏感。
- 远程桌面工具：在公司网络下能稳定连上家里电脑。

粗略时间估算（业余时间投入）：里程碑 0 和 1 各一到两周，里程碑 2 两到四周。里程碑 0 的实测结果会影响后续估算。

## 9. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 全 AI 视频进不了快手分成计划 | 整个方向没有广告收入 | 里程碑 3 先实测，拿数据前不扩大投入；必要时回头加真人成分 |
| 图生视频在 16G 显存上跑不稳或太慢 | 产能达不到隔日更 | 里程碑 0 首先验证；不行则降分辨率或换更小的模型 |
| 自动评分挑中平庸候选 | 返工率高，人工时间超过 15 分钟 | 根据返工率调评分与候选数 |
| 山海经题材同质化严重 | 推荐量低 | 靠固定画风和角色做出作者辨识度 |
| 管线被判定为同质化批量发布 | 限流或封号 | 单号、每条独立选题、手动发布 |
| 远程桌面被入侵 | 家里电脑失守 | 强密码加二次验证，不对外暴露任何端口 |

## 10. 仓库约定

- 分支：改动一律在特性分支上进行，不直接改 `main`。分支名形如 `feature/<topic>-<yyyyMMdd>`。
- 提交信息：`<type>(<scope>): <subject>`，subject 用中文。
- 提交纪律：设计文档、实施计划、具体实现各一次提交，实现阶段不拆成逐任务的多次提交。
- 不进仓库的内容：模型权重、素材、成片等大文件；API 密钥等凭据（放 `.env`）。现有 `.gitignore` 是 Python 模板，已忽略 `.env`，但尚未忽略模型权重和媒体文件，实施计划中需补上规则。
- 仓库使用 MIT 许可，设计文档里不放个人信息、密钥和内部资料。

## 11. 增补：双生视频引擎（2026-11-26）

经与项目主人确认，里程碑 1 的生视频模型同时支持两个本地引擎：

- 工作流文件按引擎命名：`workflows/<引擎>_i2v_api.json` 和同名 `.binding.json`，引擎取 `wan`（Wan 2.2）或 `minimax`（本地部署的 MiniMax）。文生图的关键帧工作流两个引擎共用。
- 用哪个引擎由配置项 `video_engine`（环境变量 `VIDEO_ENGINE`）决定，默认 `wan`；临时切换可在命令前覆盖环境变量。同一条视频只用一个引擎。
- 参数绑定允许模板未暴露的可选参数不绑；必填只有正向提示词，图生视频另加首帧图。校验命令会报出未绑定的可选参数和管线不认识的参数名。
- 第 8 节里程碑 0 的实测改为在各引擎的实际模板上做，分辨率、帧数和耗时的要求以模型支持为准；成片仍由合成统一裁到每镜 5 秒。
